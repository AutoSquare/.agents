# Git 提交说明与手动提交规范

## 触发条件

用户要求提交说明，或一次完整任务收尾需要建议提交时读取。

## 硬性约束

- 禁止 Agent 执行 `git add` / `git commit` / `git push`，除非用户在同一条消息里明确要求提交。
- Git 默认由用户本地手动提交；Agent 只生成可复制文案。
- 生成文案前只读检查 `git status --short`、`git diff --stat`，必要时读取近期提交风格。

## 文案风格（统一格式）

所有提交说明一律采用以下结构，**不要**用 Conventional Commits（禁止 `fix(rebar):` 这类英文 type 标题）。

### 结构

```
<一句话总结>

问题：
1. <现象与用户可见后果>
2. …

处理：
1. <对应处理；关键模块/文件；须重算/须重编译等>
2. …
```

### 写作规则

- **一句话总结**：首行独立成句，概括本次提交主题；可用「修复了…」「优化了…」「新增了…」等动词开头。
- **问题**：编号列表（`1.` `2.` …），每条写一个可验证的问题或现象；条数 ≥ 1。
- **处理**：编号列表，与问题尽量一一对应（第 N 条处理对应第 N 条问题）；条数 ≥ 1。
- **空行**：总结与 `问题：`、`问题：` 与 `处理：` 之间保留空行。
- 小改动也使用该格式，`问题：` 与 `处理：` 各至少 1 条。

### 示例

```
全量检查与修复了数据自检的逻辑

问题：
1. 配筋页运行前校验没有区分纵筋、箍筋和 CAD 出图阶段，ErrorProvider 提示范围不准确；
2. CAD 出图会读取箍筋弯钩内径和弯后直段长度，但缺失时仍使用默认值绘制；
3. 旧 gpdx 中向导枚举为空时，Python 侧可能把简单土层误判为岩层，导致输出 β=0 并生成错误内力结果。

处理：
1. 新增纵筋、箍筋、CAD 出图独立校验阶段，收窄各阶段必填项并补齐 ErrorProvider 反馈；
2. CAD 出图在已有箍筋分区时强制校验箍筋弯钩构造参数；
3. C# 基线补齐和 Python 后端统一兜底关键向导枚举，避免 null 漏入计算分支。
```

## 禁止

- 不使用 Conventional Commits，如 `fix:`、`feat(scope):`。
- 用 Markdown 标题或 bullet 替代编号列表。
- 不写 diff 中不存在的变更。
- 不把计划未落地项写进 message。
- 不提交密钥、`.env`、用户私有数据，除非用户明确要求。
